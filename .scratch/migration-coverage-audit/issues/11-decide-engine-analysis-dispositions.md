# Choose Dispositions for Foreground Engine and Analysis Capabilities

Type: grilling
Status: resolved
Blocked by: 01, 04

## Question

Given the cross-cutting Entry Point census, [Inventory Foreground Engine and Analysis Capabilities](04-inventory-engine-analysis.md), and the standing R3 decisions, which engine and analysis behaviors are equivalent migrations, Next redesigns, deferred, abandoned, or implementation-only; how should oversized ENG/ANA claims split into stable Parity Items; and which defaults, persistence, identity, cancellation, failure/recovery, evidence, and acceptance contracts belong in R3 versus later dependent phases?

## Answer

### Frozen claim boundary

Accepted `ENG-01`, `ANA-05`, `UI-03`, and `UI-04` keep their original scope, status, and evidence. This decision does not add engine lifecycle, Java profile fields, tracking analysis, Java in-tree cache behavior, SGF analysis exchange, or additional presentation preferences to those claims. Existing Missing and Partial items may be split below because their outstanding contracts are not accepted history.

### Canonical model

- An **Engine Profile** is saved KataGo analysis JSONL launch configuration with a stable profile identity: name, engine path, model path, config path, working directory, and max visits.
- The **Autoload Default** is the zero-or-one Engine Profile marked for startup. No marked profile means autoload is off. It is distinct from the profile selected for editing in Engine Settings and from the profile snapshot owned by the current run.
- A **Foreground Engine Run** is one manager-owned resident KataGo analysis JSONL process created from an immutable Engine Profile snapshot. Editing its source profile produces pending changes; only explicit Restart creates a run from the new profile.
- An **Analysis Job** has manager-owned run, job, and node/game scope. Jobs occupy either the selected-node lane or the whole-game lane. Supersession is lane-local; Stop, Restart, switch, crash, and application exit cancel every job owned by the affected run.
- Engine Settings edits the catalog and Autoload Default without starting or switching a run. The main-workspace Engine Switcher starts or switches the Foreground Engine Run.

### Stable Parity Item boundaries

- `ENG-02` — **Foreground Engine Run**: one manager owns the no-engine/starting/ready/stopping/error state and an immutable profile snapshot. Start validates assets and reaches ready before publishing the run. Dedicated Stop cancels every run-owned job and terminates the process. Explicit Restart cancels every old-run job, terminates that process, and replaces it from current saved profile data. Settings selection and edits never start, switch, or mutate a run.
- `ENG-03` — **Transactional Foreground Switch**: start B while A remains primary; promote only a ready B for the current switch identity; cancel A jobs, route new jobs to B, then stop A. The active profile cannot be deleted; another profile can become primary only through this transaction.
- `ENG-04` — **Failed Switch and Stale Identity Rejection**: failed B leaves A ready and primary; a superseded switch or late process/job event cannot alter current identity, status, or presentation. If A no longer exists, failure yields the explicit no-engine state rather than promoting B.
- `ENG-05` — **Cancellable Selected-node Job Identity**: the manager owns selected-node job start, explicit cancellation, completion, and supersession. Only the latest job for the current run and node may publish. Query/result correctness remains `ANA-01`; this item owns lifecycle identity.
- `ENG-06` — **Default Foreground Autoload**: the profile catalog persists zero or one Autoload Default, with none as the first-use/off default. Startup with a mark validates and starts that profile; failure reports a typed error and leaves no engine without falling back to another profile. Changing the mark does not change the current run. Deleting an inactive marked profile clears the mark; the active-profile deletion guard still applies. Persistence failure preserves the prior durable mark and reports the failure.
- `ENG-07` — **Foreground Failure and Manual Recovery**: start, asset, protocol, nonzero-exit, timeout, and cancellation outcomes are typed and scoped to the current run. Unexpected exit cancels its jobs and stays in error until explicit Restart. No automatic restart or stale event can replace the current run; profile correction occurs through Engine Settings.
- `ENG-08` — **Engine Profile Catalog Ordering**: stay Deferred. Acceptance requires user-directed first/up/down/last reordering to persist stable profile identities without changing Engine Settings selection, Autoload Default, active run, pending edits, or job binding. Rejected or failed persistence leaves the durable order unchanged.
- `ANA-01` — **One-shot Position Analysis**: submit the selected position through the manager-owned selected-node lane and expose result, typed failure, explicit cancellation, and supersession. Publication requires current run, job, document generation, and exact `NodePath`.
- `ANA-02` — **Mainline Whole-game Analysis**: one single-stage JSONL session analyzes the current game's main line, reports current/completed/remaining progress and node-linked results, supports explicit cancellation, and does not block review navigation. No two-stage, pause/resume, or lease-wait behavior belongs to this item.
- `ANA-03` — **Analysis Job Lanes**: selected-node and whole-game jobs have independent manager-owned identities and cancellation. Supersession affects only the selected-node lane. Stop, Restart, switch, crash, and exit cancel both lanes for that run, and late events are non-publishing.
- `ANA-04` — **Next-native Analysis Presentation**: candidates, PV mini-board, ownership, policy, and candidate limit render only for the current run/job/node scope. Existing hover and accepted UI behavior retain their original evidence; Java granular display preferences are not successors.
- `ANA-05` — **Analysis Cache Basics**: remains frozen Accepted. Variation-aware changes, Java in-tree cache semantics, and SGF exchange cannot be claimed through this item.
- `ANA-06` — **Continuous Current-node Analysis**: stay Deferred. Acceptance requires an explicit default-off, run-scoped workspace toggle; opening it submits selected-node work, navigation supersedes the prior request, and closing it cancels the lane. Stop, restart, switch, crash, and application exit cancel it and reset the toggle off; no startup or ready event enables it.
- `ANA-07` — **Batch SGF Analysis**: stay Deferred. Acceptance requires a session-only ordered SGF queue, visible per-file pending/running/completed/failed/cancelled state, explicit cancellation, and run/job/file identity that blocks stale publication. Queue state is not persisted or restored, and batch work cannot replace or dirty the current game.
- `ANA-08` — **SGF Analysis Exchange**: stay Deferred. Acceptance requires fixtures for frozen Java analysis-header import, structured candidates/PV/ownership where present, incomplete-placeholder rejection, Next export/reopen, preservation of personal comments and unrelated properties, and no false claim that SQLite and SGF stay synchronized.

### Phase, persistence, and evidence boundary

- R3 owns `ENG-02` through `ENG-07`. It does not include catalog ordering, continuous pondering, batch files, SGF exchange, Java GTP/SSH/profile fields, or any abandoned analysis mode.
- R4 owns `ANA-01` through `ANA-04` after the R3 manager exists. `ANA-01` and `ANA-02` use independent lanes under `ANA-03`; `ANA-04` consumes only identity-valid results.
- `ENG-08` and `ANA-06` through `ANA-08` remain Deferred with the acceptance contracts above. Ticket 15 may order them only after their named dependencies; it must not silently pull them into R3 or R4.
- The Autoload Default persists with the profile catalog. Foreground Engine Runs and Analysis Jobs never persist or recover across application restart. Continuous-analysis toggle and batch queue are session/run state, not preferences. Existing `max_visits`, Next presentation preferences, and accepted SQLite cache defaults remain unchanged.
- R3 evidence must include focused state-transition coverage for start/Stop/Restart, immutable snapshots, Autoload Default persistence, A→B promotion and rollback, active-profile deletion, typed failure, cancellation, and stale identities. A controlled JSONL fixture must exercise manager-owned selected-node job start, cancellation, supersession, and stale-result rejection. Real KataGo smoke must prove ready, Stop, Restart, and two-profile switch behavior.
- R4 evidence must exercise exact-node one-shot publication, concurrent selected-node/whole-game lanes, lane-local supersession, progress, explicit cancellation, typed failure, and presentation scoping. Deferred items require their listed acceptance fixtures only when scheduled.

Ticket 15 owns rebuilding `docs/JAVA_CAPABILITY_INVENTORY.md`, `docs/PARITY_MATRIX.md`, and `docs/MIGRATION_PLAN.md` from these decisions. Ticket 16 owns final inventory/matrix/roadmap traceability. This ticket changes neither production behavior nor those tracked destination documents.
