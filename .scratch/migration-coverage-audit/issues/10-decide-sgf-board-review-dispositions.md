# Choose Dispositions for SGF, Board, and Review Capabilities

Type: grilling
Status: resolved
Blocked by: 01, 03

## Question

Given the cross-cutting Entry Point census and [Inventory SGF, Board, and Review Capabilities](03-inventory-sgf-board-review.md), which uncovered baseline behaviors require equivalent migration, deliberate Next redesign, defer, abandon, or Swing-only exclusion; which existing Accepted R1/R2 claims remain complete at their original scope; and which new Successor Items and acceptance conditions are required without reopening or silently expanding those claims?

## Answer

### Frozen claim boundary

Accepted `SGF-01` through `SGF-06`, `RULE-01`, `UI-01`, `UI-03`, `UI-04`, and the claimed `UI-05` action inventory remain complete at their original scope, status, and evidence. `UI-02` remains Partial only for engine events during a mutation owned by domain 04. None of the decisions below reopens those items or adds adjacent behavior to their acceptance history.

### New Successor Item boundaries

- `SGF-07` — **Safe Current-game Replacement**: every in-application SGF text/file replacement parses and validates a candidate before commit. The current-game owner then resolves Save / Discard / Cancel and any domain-05 ownership gate. Failure or cancellation preserves the tree, selected `NodePath`, source path, dirty state, review presentation, and recent-file state. Success atomically installs one candidate, selects its deterministic initial path, clears stale generated presentation, and updates source/recent state only for a real file open. `APP-01`, `APP-02`, and domain-06 import call this seam.
- `SGF-08` — **GIB Current-game Import**: fixtures cover names, komi, passes, ordinary moves, 5/7/9-stone handicap placement, line-ending handling, malformed/empty input preservation, and Save As SGF. A successful import has no writable GIB source identity and follows `SGF-07`.
- `SGF-09` — **Recent Kifu Intake**: successful SGF/GIB file opens add a deduplicated persisted entry; cancelled or failed opens do not. Selecting an available entry follows `SGF-07`; an unavailable or invalid entry reports its path and leaves the current game unchanged. Clear Recent History removes only this persisted list; cancellation or persistence failure preserves the durable list.
- `SGF-10` — **New Game Document**: all New/Clear entry points use `SGF-07`, then create one untitled empty SGF document at root with a supported chosen board size, the default komi, default player names, no source path, and clean state until the first edit. Cancelled dirty-state resolution preserves the old document.
- `SGF-11` — **Starting-position Editor**: black, white, erase, side-to-play, clear, and convert-current-position actions update `AB`/`AW`/`AE`/`PL` at the selected setup node; board preview and `NodePath` remain synchronized; cancel/rejection is non-mutating; save/reopen preserves the setup.
- `SGF-12` — **Structural Tree Editing**: delete-current-move, undo/redo, promote-to-main, and return-to-main preserve unaffected siblings and properties, return a valid `NodePath`, and keep board/comment state synchronized. Undo restores the exact prior tree and cursor; redo restores the exact edit; the final tree survives save/reopen.
- `SGF-13` — **Game Metadata Editor**: player names and komi are initialized from the current root, validated, and applied atomically to root properties. Cancel or validation failure leaves tree and dirty state unchanged; accepted edits update the active komi and survive save/reopen. Board size remains a New Document choice under `SGF-10`.
- `SGF-14` — **Interactive Markup**: labels, circles, squares, crosses, triangles, and numbered marks can be created, replaced, and removed on the selected node without disturbing unrelated SGF properties. Board rendering follows selection and save/reopen preserves the exact supported marks.
- `REVIEW-01` — **Direct Review Navigation**: selecting a visible move or variation in a Next-native tree/list chooses its exact `NodePath` without editing the tree. Board position, move number, personal comment, and owner-scoped analysis presentation follow that selection; domain-04 graphs reuse the same command.
- `REVIEW-02` — **Try-play Sandbox**: enter from any selected node, play legal trial moves and passes, navigate the trial line, and exit back to the exact authoritative node. Entering, playing, and exiting do not change the SGF tree, source path, dirty state, comments, or saved output.
- `REVIEW-03` — **Position Scoring**: enter from the selected position, mark/unmark dead groups, and show deterministic black/white totals and lead under both area and territory scoring with current komi. Area is the first-use default; the selected rule persists through `PREF-01`. Preview, dead-group markings, and rule switching do not edit the SGF or dirty state. Explicit Confirm Result atomically writes the displayed result to root `RE`, marks the current game dirty, preserves all other root properties, and survives save/reopen.
- `REVIEW-07` — **Board Display Preferences**: coordinate visibility and the current Next all-move-number boolean apply immediately, default to on/off respectively, and persist through `PREF-01`. Keyboard/menu controls and rendered board stay synchronized; persistence failure follows the `PREF-01` durable-value contract.
- `REVIEW-08` — **Review Move Sound**: successful local moves, passes, and forward review navigation play one move sound when the default-on preference is enabled; rejected actions, parsing, bulk tree rewrites, and disabled sound remain silent. The preference persists through `PREF-01`; synchronization muting remains domain 06.

### Deferred Successor Items

- `SGF-15` — **Direct Stone Manipulation**: forced black/white/alternating insertion, move-list insertion, and stone drag stay Deferred. Acceptance requires explicit SGF setup/move semantics, bounds/occupancy validation, preservation of unrelated branches/properties, reversible edits, non-mutating rejection, and save/reopen coverage.
- `SGF-16` — **Whole-tree Transforms**: color swap, rotate, and mirror stay Deferred. Acceptance requires every supported coordinate-bearing move, setup, and markup property to transform consistently across all branches while `NodePath` structure and unrelated metadata remain stable; color swap also exchanges color-owned properties; serialize/reparse preserves the result.
- `REVIEW-04` — **Board-point Move Search**: double-click/search navigation stays Deferred. Acceptance requires deterministic traversal to matching moves across branches, exact `NodePath` selection through `REVIEW-01`, and a non-mutating no-match result.
- `REVIEW-05` — **Configurable Main-board Autoplay**: main-board interval control stays Deferred. Acceptance requires a validated persisted interval, one active timer, deterministic selected-`NodePath` progression along the chosen continuation, stop at a leaf or scope change, and no change to the accepted fixed-toggle history in `UI-05`. Candidate-variation, sub-board, and engine-best-move replay remain domain 04.
- `REVIEW-06` — **Ladder Continuation**: automatic ladder continuation stays Deferred. Acceptance requires a reproducible ladder predicate, legal continuation from the selected node, explanatory refusal below the supported threshold, and no partial tree mutation on failure.
- `EXPORT-01` — **Current-branch SGF Export**: stay Deferred. Acceptance requires export of the selected root-to-leaf branch as a standalone main line whose semantic reopen matches that path, without mutating current tree order, source path, cursor, or dirty state.
- `EXPORT-02` — **Review-board Image Export**: stay Deferred. Acceptance requires export of the current main-board review view to a documented image format and size without changing current-game or review state. Analysis/sub-board/win-rate image exports require their owning domain-04 disposition.

Existing Accepted items keep their original evidence and status. Ticket 15 owns phase ordering; Ticket 16 owns final inventory/matrix/roadmap traceability. Deferred item acceptance is recorded now so later roadmap work cannot silently broaden it.
