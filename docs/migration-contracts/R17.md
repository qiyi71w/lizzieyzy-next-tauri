## F01 — Decide hostname-reset and initialization user goals individually

Current capability: [R17 — 保留初始化和主机变更用户目标](../R17_PLAN.md#initialization). Historical source: `01-startup-preservation-decision.md`.

### Functional input scope

No predecessor ticket; fixed inputs below. Any acceptance-time external environment/approval is stated explicitly.

### Behavior and decision contract

Resolve hostname-triggered deletion and initialization/settings-wizard goals from original decisions and approvals without silently wiping preferences.
Inputs: Inventory SET-FIRST-LAUNCH hostname-wipe half and SET-FIRST-USE, Ticket09, WINDOW-01 invalid-geometry reset, PREF-01 categorized preferences and engine bootstrap owner. Hostname lookup failure must not fake a machine change. Determine retained user goals, initial/default/explicit action, data ownership and cancel/failure semantics, or item-specific approved non-equivalent reason. Do not invent a forced wizard or expand geometry reset to semantic settings; no automatic engine start/download. Output one independently traceable disposition per H03/H04 and an executable retained setup contract if applicable.

### Guardrails and non-goals

Keep Rust current-game/session authority, Tauri gateway/API wrappers, one engine/Match lifecycle and no implicit engine switching. Cancel/failure preserves current SGF; late document/node/session/run/job/account results cannot mutate replacement state. Personal C and generated information remain separated under ADR0003; credential/network boundaries remain intact and account writes never auto-retry. Use existing mechanisms and per-owner Java field mappings; do not reproduce Swing machinery or hypothetical Java defects. No new permanent non-equivalent cut without item-specific approval.

A owns T02-I18N-FOUNDATION within T03-NAV-GLOBAL-FUNCTION-SEARCH. Consume only validated key/locale/fallback shared result, not the whole search feature; full translations are F-owned. B owns T01-RESOURCE/T01-DIAGNOSTICS shared results; C owns T01-NETWORK; this source contract adds only its actual consumer boundaries. Installed package validation and engine compilation are separate from application/engine/service functional proof. Existing partial/browser/fixture evidence never substitutes for required native/real-service evidence.

### Observable acceptance

- H03/H04 each identify old source/decision/approval, unmatched user goal and approved retained contract or non-equivalent reason.
- Hostname change/missing identity, first use, explicit initialize, defaults, save/cancel/failure and field mapping are explicit; invalid-geometry reset remains narrow.
- No unapproved preference deletion/forced onboarding occurs and missing approvals keep F02 needs-info.

### Owner/source and evidence mappings

- Owner intents: `T02-H03`, `T02-H04`.
- Source intents: `T02-H03`, `T02-H04`.
- Parity scope: `WINDOW-01`, `PREF-01`.
- Decisions may share routing with their explicitly blocked implementation; their completion is not that implementation's acceptance. Aliases remain source keys only.
- Full behavior authority: [Matrix](https://github.com/qiyi71w/lizzieyzy-next-tauri/blob/15b71e8bd89349961b7cf25f2fd2a6928e991e40/docs/PARITY_MATRIX.md), [Inventory](https://github.com/qiyi71w/lizzieyzy-next-tauri/blob/15b71e8bd89349961b7cf25f2fd2a6928e991e40/docs/JAVA_CAPABILITY_INVENTORY.md), [UPSTREAM_DELTA](https://github.com/qiyi71w/lizzieyzy-next-tauri/blob/15b71e8bd89349961b7cf25f2fd2a6928e991e40/docs/UPSTREAM_DELTA.md). ### Validation ownership, inherited evidence and native gaps

Inheritance invalidates at changed consumed behavior, DTO/protocol, document/node/session/run/instance/account identity, resource/model/client version, platform or target service.
