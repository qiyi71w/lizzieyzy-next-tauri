# LizzieYzy Next Architecture

LizzieYzy Next is the Tauri 2 + Rust + TypeScript desktop architecture being built beside the Java/Swing maintenance line. The goal is to move user-visible behavior into smaller testable domains without claiming full legacy parity before the evidence exists.

## Current System Shape

```mermaid
flowchart LR
  UI["React + TypeScript UI\napps/desktop/src"] --> API["Frontend API wrappers\n@tauri-apps/api"]
  API --> Tauri["Tauri 2 command gateway\napps/desktop/src-tauri"]
  Tauri --> Model["app-model DTOs"]
  Tauri --> SGF["sgf\nparse / replay / serialize"]
  Tauri --> Go["go-core\nboard rules"]
  Tauri --> Kata["katago-protocol\nanalysis JSONL"]
  Tauri --> Engine["engine-manager\nrun / jobs / process"]
  Tauri --> Analysis["analysis-core\nmarkers / sorting"]
  Tauri --> Prefs["app-preferences\napp data JSON"]
  Tauri --> Recovery["current-game-recovery"]
  Tauri --> Match["match-core\nroles / turns / terminal rules"]
  Engine --> KataGo["Local KataGo process"]
  Prefs --> AppData["Tauri app data"]
  Recovery --> AppData
```

The UI consumes DTOs and view models. It does not consume raw KataGo JSON and does not own long-running engine processes. `engine-manager` owns the Foreground Engine Run, Analysis Jobs, and process lifetime. Rust owns file I/O, SGF parsing, process execution, cancellation, and app-data persistence.

Provider and readboard live paths follow the same boundary rule. The React UI should enter these paths through frontend API wrappers and Tauri commands; provider HTTP parsing, readboard sidecar probing, protocol parsing, and DTO normalization belong behind Rust crate boundaries. A wired command path is repository evidence only. It is not evidence that the external Yike/Fox services, accounts, network, or a local readboard sidecar have been validated.

## Modules

### `apps/desktop`

React + TypeScript desktop UI built with Vite. The current UI includes board rendering, SGF text/import workflow, native SGF/GIB open and SGF save entry points, winrate and analysis panels, and engine profile controls.

The browser preview can exercise UI fallback paths and local demonstration analysis, but it cannot perform native file dialogs, authoritative current-game edit/Save, app-data profile or recovery persistence, local asset checks, or real KataGo execution.

`apps/desktop/src/workspace` owns left/right ratio drafts, their visible projection, pointer/keyboard resizing, and element measurement. `useWorkspace` exposes the persistence owner and default restoration; `projectWorkspace` and `resizeWorkspace` are pure, and `Workspace` consumes them without IPC. App retains SGF, selected-node and analysis ownership. Visible column minima are 210/360/240 CSS px with separate 8px separators; insufficient space scrolls rather than changing preferences. Unset shares use 228/260px above 1180px workspace width, otherwise 210/240px. Hidden shares remain stored, their pixels go to the center, and finite nonnegative shares must sum below one; a large hidden share can therefore limit the remaining rail's custom proportion. Separator bounds report that feasible range.

Main board, sub-board and winrate chart consume `useElementSize` (ResizeObserver, DPR change and window resize). Zero-size surfaces wait for visibility; unchanged measurements are filtered before scheduling React state. Bitmap dimensions track measured CSS content dimensions times DPR independently of analysis frames. Rectangular board geometry and input callbacks remain owned by their existing consumers.

Nullable `workspaceShares: { left, right }` is stored in the existing app preference file; missing or invalid ratios load the default strategy. The narrow `update_workspace_shares` command merges under `PreferencesState`'s transaction lock, atomically persists, then publishes. Ordinary full preference saves retain the backend's committed ratios. Layout writes do not re-admit analysis. The frontend renders drafts immediately, coalesces for 500ms and serializes writes; stale completions cannot replace newer drafts or clear their pending/error state. The fixed tool area reports saved/pending/saving/unsaved and Retry saves the newest draft. Display → Restore panel sizes and Preferences share one action, changing only ratios to `null`; viewport clamps are never persisted.

File Exit and native Close drain layout, window geometry, rail visibility, native pin transactions and ordinary preference writes (including theme) before document departure. The shared drain has a five-second deadline and Retry/Cancel close on failure; it includes writes queued behind an active preference save. A failed preflight does not enter document departure or stop analysis. The existing workspace freeze owner rejects new R7 edits in handlers and disables their controls while document confirmation is active or a committed final drain remains incomplete; cancellation restores interaction and retains drafts. `finishNativeExit` repeats the all-owner drain, and Rust `confirm_native_exit` seals the latest native geometry immediately before `app.exit`. Existing document Save/Discard/Cancel, recovery and teardown contracts remain authoritative.

Nullable `windowGeometry` shares the existing atomic preference file. Its outer origin is physical pixels; client dimensions are logical pixels with the sampled `scale_factor`, and `maximized` is independent of normal bounds. The Rust window actor serializes native sampling, 500ms coalesced narrow saves, reset, Retry and exit flush without holding the preference mutex across OS calls. Minimized and transitional bounds cannot replace normal geometry. Full preference saves preserve the committed geometry just as they preserve workspace shares and Recent history.

On native Wayland, `windowGeometry.x` and `y` are both `null`: the compositor owns placement and the actor restores only logical client dimensions and maximization. Numeric origin pairs remain the Windows/X11/macOS wire contract. A mixed null/numeric origin is invalid. Wayland startup does not require a primary monitor or global coordinates, and unavailable positioning does not fail the exit fence. Reset uses the current output's available client dimensions without moving or centering the window; the compositor enforces placement constraints. Returning a null-origin record to a positioned backend uses the normal reachable-default recovery policy.

`app-preferences::window_geometry` owns deterministic sampling and restore policy. Valid, title-reachable saved rectangles remain in place; invalid rectangles fit the default 1440×900 client to the primary work area. A reachable rectangle needs at least 100 logical pixels of draggable width and `min(32, native draggable caption height)` logical pixels of draggable height wholly within one work area. Windows uses native caption metadata and `WM_NCHITTEST` to exclude the system icon, caption buttons and resize borders. Linux measures a native GTK HeaderBar and its allocated internal controls on the GTK thread: X11 installs that GTK decoration, while Wayland retains Tao's existing HeaderBar. GTK child visibility is measured independently of the hidden toplevel; client size excludes the header and CSD border, and restored outer positions account for GTK's gravity offset. AppKit queries the NSWindow title strip and visible standard-button bounds on the main thread. Neither non-Windows adapter uses a fixed 32-pixel estimate. Native platform acceptance remains separate from source implementation and API type-checking; a compositor/window manager can constrain requested placements.

Display and Preferences share an explicit current-monitor centered, unmaximized reset that changes only geometry. Monitor-query failure fits an independently readable primary work area for display only, retains durable geometry and suspends saving until Retry succeeds. If both queries fail, the existing OS window is shown with the failure reported. Startup applies geometry while hidden, then shows the main window even on failure. Browser preview exposes the desktop-only limitation and disables reset; native geometry is not browser window state.

Geometry autosave preserves an unconsumed preference-recovery notification. A pending move returning to already-durable bounds publishes `saved` even when no disk write is needed.

Expanded setup/scoring controls remain in the diagram's scrollable flow. Their intrinsic grid rows keep the toolbar, minimum-sized board and controls separate when vertical space is insufficient.

`AppPreferencesDto.workspaceVisibility` owns independent durable `left`/`right` visibility (both initially true), with its shared value type in `app-model`. `update_workspace_visibility` merges optional sides into the latest preferences under the existing `PreferencesState` transaction lock and returns only visibility; ordinary full preference saves preserve this owner field. UI controls commit after a successful write, retain the old state on failure, and remain available outside both rails. Hidden rails stay mounted to preserve comment drafts, AnalysisPanel tabs and node/candidate identity, but have no grid pixels, separator, focus or accessibility surface. Hiding the chart clears hover; focus inside a closing rail moves to the fixed restore control. Replay is eligible on the visible candidate-enabled main board or the visible Variation sub-board; losing both surfaces pauses without resetting the retained prefix. Hiding does not mutate SGF or stop engine analysis. Browser preview uses the same merge semantics in localStorage; native app-data/restart evidence is separate.

Personal comments remain local drafts until the explicit `应用评论` action; blur and rail visibility changes never commit them to SGF. Focus on a closing rail's separator also returns to the fixed restore control before that separator is removed.

### `apps/desktop/src-tauri`

Tauri 2 command gateway. It exposes health, SGF parse/replay, native SGF read/write, engine profile persistence, asset checks, and manager-owned Foreground Engine Run commands (`foreground_engine_snapshot`, `foreground_engine_start`, `foreground_engine_stop`, `foreground_engine_restart`, `foreground_engine_switch`, `foreground_engine_start_selected_node`, `foreground_engine_cancel_job`). Whole-game analysis on a Ready Run uses `katago_start_analyze_game` / `katago_cancel_analysis`. Current-game replacement uses `prepare_document_replacement` / `resolve_document_replacement`. Application exit uses `prepare_application_exit`, `resolve_application_exit`, `retry_application_teardown`, `confirm_application_exit_anyway`, and `confirm_native_exit`. Current-game recovery uses `inspect_current_game_recovery`, `restore_current_game_recovery`, `discard_current_game_recovery`, `retry_current_game_recovery`, and `current_game_recovery_protection`. Removed profile-to-process commands `katago_analyze_once` and `katago_analyze_game` are not registered. Native `fake_analyze` is not registered; browser-preview demonstration analysis remains non-authoritative and does not create a Foreground Engine Run.

Desktop engine command results, including match-owner operations and match-default persistence, use the Rust-only `EngineCommandResult<T>` alias with `Box<EngineFailureDto>` errors; serialization retains the existing error DTO fields and casing. Replacement and exit orchestration take named `ReplacementResolution` / `ExitResolution` requests internally. Their Tauri command payloads and managed recovery-store ownership remain unchanged.

Native chooser intake uses `read_game_file`; the sheet file input uses `import_game_bytes`. Both return `GameFileImportDto` (`format`, canonical `sgf_text`, display path/name, optional writable `native_path`, optional `opened_path`) and then enter the same document-replacement owner. Native reads canonicalize the source path and retain it as `opened_path`; byte imports have no `opened_path`. SGF/TXT retains its native path. GIB is decoded and normalized by the `sgf` crate and always returns `native_path = null`, so ordinary Save uses Save As and can never overwrite the source GIB.

Native SGF/GIB activation and main-window OS file drop share one Tauri gateway admission owner and at-most-once delivery slot. Activation resolves each file argument against the requesting process's working directory and focuses the existing `main` window; a drop supplies its native path directly. The cold-start request remains in Rust until the frontend has loaded preferences and inspected recovery. An abnormal recovery decision completes before that retained request enters `read_game_file` and the existing document-replacement owner; a normal explicit file suppresses `restoreLastSession` and sample loading. File picker, Save, replacement, recovery, and exit flows mark external-file admission busy, so later activations or drops are rejected rather than queued. No-file launches only focus; directories, unsupported types, and multiple files are explanatory non-mutating rejections.

After a native file replacement commits, chooser, activation, drop and recent reopen consume the same `opened_path` event and call `update_recent_game_history`. `app-preferences` retains five paths, newest first, deduplicating canonical paths and OS file identity (including hard links). File → Recent shows filenames with full-path tooltips, reopens through the existing safe replacement owner, and offers Clear and explicit failed-write Retry. Recent slots use Alt+1–5, Clear uses Ctrl+Shift+Delete, and Retry uses Ctrl+Shift+R through the focus-safe Shortcut Registry. Byte imports, sample, paste, New, recovery and Save do not record file-open events.

This layer should stay a gateway. Domain behavior belongs in crates unless it is directly about Tauri lifecycle, app data paths, command shape, or event emission.

Rust owns the authoritative current game. The holder stores `CurrentSgfDocument`, a monotonic semantic position/tree `generation`, `dirty`, `native_path`, the selected `NodePath`, and recovery sequence counters (`document_seq`, `snapshot_seq`). Shared results use `CurrentGameResultDto` (`tree`, `selected_path`, `snapshot`, `generation`, `snapshot_seq`, `dirty`, `native_path`). Comments, navigation and ordinary Save preserve `generation`; accepted move/tree edits and document replacement advance it. `snapshot_seq` orders document content and Save state within that identity, so delayed analysis snapshots cannot overwrite newer comments or saved/dirty state. Domain failures stay in `CurrentGameError` / `CurrentGameErrorKind`. Filesystem Save failures stay Gateway `String` errors and do not extend the domain kind enum.

Current-game mutation and derived reads are `select_current_game_node`, `play_current_game`, `set_current_game_personal_comment`, `set_current_game_metadata`, `edit_current_game_markup`, `apply_root_setup`, `convert_to_root_setup`, `remove_current_game_variation`, `promote_current_game_to_main`, `serialize_current_game`, `save_current_game`, `save_current_game_as`, and `project_current_game_mainline`. Native document replacement prepares and resolves a candidate rather than installing SGF in one command. `play_current_game` sends a `NodePath` plus point/pass vertex; Rust uses the selected position's player-to-play color and `go-core` legality. An identical existing child is selected without mutation. A new child increments document generation and marks the game dirty. Occupied, suicide, simple-ko, and invalid-path failures are atomic.

`set_current_game_metadata` takes the caller's semantic `generation` and atomically edits root `PB`, `PW`, and finite `KM`; it preserves `HA` and unrelated SGF properties. The original root values initialize the editor. One effective Apply produces one document-history unit; Cancel, invalid komi, stale generation, and no-op produce none. Name-only edits preserve generation, attached analysis, and active tasks. A changed komi advances generation, removes now-inapplicable attached `LZ`/`LZ2` analysis across the tree, invalidates old jobs/tasks, and re-admits continuous analysis with the new condition. Undo/Redo exchange the affected analysis attributes with the corresponding komi condition without restoring Run/Job/Task identities. The HUD reads current root names directly, preserving nonblank text and falling back to 黑棋/白棋 for missing or whitespace-only values; long values retain their full accessible title.

`undo_current_game` and `redo_current_game` take the caller's `generation` and return the same authoritative result, including `can_undo` and `can_redo`. The Rust document owner retains at most 100 effective user commits across move/pass insertion, personal-comment Apply, root metadata Apply, node markup, root setup/conversion, subtree deletion and mainline promotion. Navigation, choosing an existing child, failed/no-op edits, Save, preferences and analysis reports do not create commits. An effective edit after Undo discards the redo branch. The Shortcut Registry routes document Undo/Redo only outside editable text controls.

History reverses affected properties or subtrees and restores the exact pre/post-edit cursor. It does not restore a whole-document snapshot: unrelated analysis accepted since the edit remains attached. Structural and komi reversals advance semantic generation and invalidate old analysis/task identities; name, comment and markup reversals preserve generation and do not cancel unrelated work. Neither direction restores a Run, Job or Task.

The extension seam is `sgf::DocumentEditOutcome`: an effective domain operation returns its resulting snapshot and one opaque `SgfDocumentEdit`; a no-op returns no edit. `CurrentGameHolder::commit_edit` admits that unit and its revision to `sgf::DocumentHistory`. Domain Undo/Redo applies the inverse and returns `DocumentHistoryOutcome` with the exact cursor and structural flag. New authoring operations must supply affected-content inverses through this same seam, then let the holder advance generation, snapshot ordering and dirty state. Unrecorded content changes use the independent content revision; navigation does not.

`remove_current_game_variation` and `promote_current_game_to_main` take the caller's `generation` with the exact `NodePath`. Delete cuts the selected non-root subtree and selects its parent; a node with children requires confirmation in the UI. Root Delete enters the existing safe New/Clear document flow. Promote moves the selected child to index zero at every branching ancestor while preserving the relative order and content of other siblings; the resulting path selects the same node. Its history inverse moves the original nodes back without copying the whole tree, including attached analysis. Already-main is a no-op. Return-to-main navigates to the mainline ancestor preceding the first off-main child, changing neither document content nor history. Structural edits and their reversals advance `generation`, invalidating old path-bound analysis and task work.
`apply_root_setup` accepts the selected childless root's complete stone set and player to play under the current `generation`; Rust validates rectangular board coordinates and duplicate points before one history commit. The UI previews black/white/erase/clear/PL locally and Cancel leaves the authoritative document untouched. `convert_to_root_setup` requires explicit UI confirmation and the exact selected path/generation; Rust replays that selected branch (including imported intermediate setup and pass), replaces the root position, and removes the move tree. It retains other root properties, the personal root comment and the native source path, while removing root analysis whose position no longer applies. Both edits reverse through the same document history, restore the previous tree/cursor on Undo, advance semantic generation and invalidate old analysis/task identities; neither starts or restores an engine.

Successful Save retains history and records the invocation-time savepoint. Dirty compares the current edit state and independent content changes against that point; later analysis cannot be cleared by returning to a saved history position. Save As adopts the new source path independently of history. Failed/cancelled Save does not move the savepoint. Successful document replacement or recovery starts with empty history; cancelled replacement preserves it. Recovery persists document content and dirty state, not history.

`select_current_game_node` requires the caller's `generation` alongside the exact `NodePath`; stale identities, invalid paths and pending departures fail before cursor/recovery/analysis changes. The frontend coalesces rapid requests within that identity and never publishes a superseded selection. Complete-tree, Selected Review Line, chart and problem-list links carry actual paths; jump-to-move counts B/W nodes including pass, skips setup/comment nodes, and uses zero for root. Navigation preserves SGF content and dirty state. Analysis accepted later retains its independent dirty semantics.

The selected snapshot includes `markup: SgfMarkupDto[]`, projected in Rust from that node's LB/CR/SQ/MA/TR properties (including compressed point lists). The board renders this snapshot alongside its position and comments. Invalid annotation coordinates are omitted from presentation while the original properties remain preserved in SGF. `edit_current_game_markup` accepts a selected `NodePath`, `generation`, and a point tool or Clear action; the Rust owner rejects stale selection/document identity and off-board points. LB text, sequential letters/numbers and CR/SQ/MA/TR replace or erase only supported markup at the point; Clear removes only supported markup on that node. Effective actions enter document history without advancing semantic generation, cancelling range tasks or replacing unrelated analysis. The frontend offers focus-safe tool shortcuts and requires explicit Apply for text.

`stone_move_numbers: MoveDto[]` in the selected snapshot identifies successful moves whose stones survive on its actual root-to-node line. Rust replay removes captured sources and clears setup points (including same-color setup); pass advances the move count without a point label. The main board consumes this projection rather than first-child moves or path depth.

`enter_trial` / `exit_trial` transition the current-game owner through Review → Entering → Active → Leaving → Review. `sgf::TrialLine` retains only the entry's replay ancestry and trial descendants; the entry appears as move zero, while the original tree, savepoint, source path, history and recovery stay authoritative and untouched. `TrialSessionDto` carries a separate session ID and monotonic revision; `trial_select`, `trial_play`, `trial_undo` and `trial_start_finite` reject stale IDs/revisions. Trial edits use an independent undo stack and do not offer a commit-to-document path. `trial://analysis` carries only session snapshots after selected-node Job identity, revision and position checks; original SGF analysis attachment is blocked throughout the temporary mode.

Entering seals current Job publication, pauses any active whole-game Analysis Task without clearing its completion set, and awaits selected/whole-game target cancellation (five-second bound). Failed cleanup reports failure and leaves the original document intact. The manager follows trial positions for the existing continuous selected-node lane and accepts finite trial jobs on that lane; the original continuous intent is retained. Leaving cancels trial queries before resuming the original selected position, without automatically continuing a paused whole-game task. Save/Copy/recovery always use the authoritative document. Departure admission validates the replacement or original dirty decision before sealing trial analysis; Cancel leaves the trial alive, while a confirmed replacement discards it with the document transition.

`enter_scoring` / `update_scoring` / `exit_scoring` reuse the temporary-mode admission and cancellation fence but do not submit KataGo queries. Rust freezes the selected position, owns dead-group and neutral-point correction, and computes area (living stones plus owned empty points) or territory (owned empty points plus actual captures plus opponent dead stones). A dead stone's now-empty point can be owned once as territory; neutral points do not score. White receives the document's finite komi and, in area mode only, optional 0, h, or max(h−1, 0) handicap compensation. Explicit root HA or setup with a recognizable ruleset can initialize compensation; the user can correct nonnegative h without editing HA/RU/KM. Preview and Cancel do not mutate SGF; Confirm writes only root RE from the same unrounded result string, creates one nonstructural history edit, and preserves applicable analysis and paused task completion. Save/Copy/recovery and safe departure remain authoritative over the original SGF; scoring and trial are mutually exclusive. The UI sends scoring actions through API wrappers, and the scoring rule persists as `scoringRule` in the existing atomic preferences transaction.

Ordinary `save_current_game` writes a caller-supplied path. Ordinary `save_current_game_as` owns the Save As dialog: cancel returns `null` (`Save cancelled.`); a chosen allowed path writes through `save_current_game`'s path; a dialog-denied or Windows-redirected path is a Gateway write failure (`failed to write`) and does not write, adopt, or clear dirty. The `save-as-dialog` crate classifies those outcomes without a new harness. Successful ordinary Save keeps the caller-supplied `NodePath`, does not increment `generation`, and does not admit a document departure or cancel analysis. Directory-as-file write failure remains `current_game_save_write_failure`. Save is a semantic SGF round-trip, not byte-for-byte format preservation.

Confirmed replacement and application exit share a document-departure owner. `prepare_document_replacement` parses and validates the candidate before admission; a dirty holder returns `needs_decision`, a clean holder returns `ready`. `resolve_document_replacement` then takes Save / Discard / Cancel. Cancel aborts without sealing. Confirmed Discard or Save can stop Analysis Jobs; successful commit installs one candidate at its default selected path, clears dirty, and adopts the candidate source path. Cancelled or failed departure Save keeps the current game, keeps the engine, and stops analysis. `prepare_application_exit` / `resolve_application_exit` reuse that dirty gate for File Exit and window close (`application-exit-requested`). After confirmed leave, teardown uses a 10s budget, with `retry_application_teardown` and `confirm_application_exit_anyway` for outstanding resources, then `confirm_native_exit` to end the process. Exit dispositions recorded on the recovery envelope are `clean_completed`, `explicit_discard`, and `exit_incomplete`.

`serialize_current_game` and `project_current_game_mainline` are derived reads. The only remaining first-child adapter is the fresh Rust mainline `GameDto` consumed by analysis and review. React must not treat original `sgfText`, independently replayed positions, or `GameDto.moves` as document authority. The SGF textarea remains load input. Browser preview keeps edit and authoritative Save unavailable and explains that they need the native runtime.

Provider/readboard command contracts in this batch:

- `provider_fetch_yike` is the Tauri entry point for Yike runtime fetch. It must validate the request provider and timeout, call the Yike provider runtime path, and return `ProviderFetchResult` on success or a typed `ProviderError` on auth, network, payload, timeout, or runtime unavailable states.
- `provider_fetch_fox` is the Tauri entry point for Fox runtime fetch. It must validate the request provider and timeout, call the Fox provider runtime path for supported `chessid`, `uid`, and `user_name` commands, and return normalized provider DTOs or typed errors.
- `readboard_sidecar_probe` is the Tauri entry point for checking whether the local readboard sidecar is available. Its boundary is process/path/protocol readiness; it must not imply that a target board has been synced.
- `readboard_sidecar_sync_snapshot` is the Tauri entry point for syncing a snapshot through the sidecar. Its boundary is sidecar protocol line parsing and DTO normalization from supported inputs. Image OCR remains unavailable unless the sidecar/runtime explicitly supports it and should return a structured unsupported/not-implemented error rather than a false success.

The Provider panel is the expected UI surface for provider fetch, readboard probe, and readboard sync controls. Browser-preview behavior may show local fallback or structured unavailable states, but only the Tauri desktop runtime can exercise native provider/readboard commands.

### `crates/app-model`

Shared DTOs for games, typed file-import results, moves, positions, candidate moves, analysis frames, engine profiles, assets, health, and problem markers.

### `crates/go-core`

Pure Go board and rules logic. It has no UI, Tauri, storage, or process dependency.

`Board::score` flood-fills empty points and marked-dead stones against living group borders, excluding individually marked neutral empty points. It returns exact integer counts and ownership for the selected rectangular position; komi and handicap arithmetic stay in the Rust scoring session, not the canvas.

Boards have independent width and height, each 2–25. Current-game wire DTOs expose `board_width` and `board_height`; Go indexing, SGF setup/replay, main/sub-board rendering, PVs and analysis heatmaps use width as the row stride and height for ranks. KataGo receives `boardXSize` and `boardYSize`. Square provider/readboard inputs normalize to equal dimensions at their existing adapter boundary. The unrelated storage tables and external readboard protocol retain their existing square schema.

File New, Clear Board and Set Board Size share a parameter form and the existing document-replacement owner. Opening/cancelling that form does not seal analysis. Successful creation installs a clean root-selected untitled document; the first content edit makes it dirty. SGF uses `SZ[n]` or `SZ[w:h]`, defaults missing SZ to 19×19 and rejects malformed/out-of-range explicit dimensions. Durable `defaultBoardWidth`, `defaultBoardHeight` and `defaultKomi` default to 19, 19 and 7.5; per-document dimensions, finite komi and names do not rewrite defaults. Existing departure Save failure and explicit Resume safety holds remain unchanged. Engine dimension refusals fail the analysis Job with a capability explanation while retaining the Ready Run.

### `crates/sgf`

SGF parsing, replay, and serialization plus Tygem GIB import. GIB accepts UTF-8 or GB18030 text, maps names, authoritative komi, ordinary moves, pass, and supported handicap setup into a validated SGF tree, and rejects malformed or illegal input before replacement. The crate preserves the parsed SGF tree for compatibility paths while exposing normalized game and position DTOs to the rest of the app.

### `crates/katago-protocol`

KataGo analysis JSONL query/response modeling and normalization. Raw engine JSON should remain here or in engine-manager helpers; the UI should receive `AnalysisFrameDto`.

### `crates/analysis-core`

Analysis-derived helpers such as candidate sorting and problem marker classification.

### `crates/engine-manager`

Engine profile catalog, Autoload Default, asset checks, and the manager-owned Foreground Engine Run: lifecycle snapshot, Start/Stop/Restart/Switch, selected-node and whole-game Analysis Jobs, process execution, cancellation, and typed failure.

Profiles separate the common launch fields (`name`, `program`, ordered `argv`, optional `working_dir`) from discriminated `adapter_kind` / `settings`. A whitespace-only working directory is treated as absent; nonblank paths retain every byte, including leading and trailing spaces. `kata_go_analysis` owns model/config paths and finite `max_visits`; `generic_gtp` has an empty settings object. Each argv item is one process argument, including empty strings and whitespace; no shell parsing is involved. KataGo owns the analysis subcommand and model/config flags; conflicting user arguments are rejected rather than rewritten.

Catalog version 1 keeps stable record IDs, order, settings selection and optional Autoload Default. Legacy unversioned collection and single-profile files are decoded only at the persistence boundary. Reads never rewrite the file or start a process. Unknown versions, malformed adapter settings and save failures remain observable and preserve the previous catalog and runtime. Explicit saves validate structure and atomically replace storage; executable/model/config existence is checked at Start, not Save. An unconfigured default profile is not a Ready Run.

Saved configuration, the adapter's static capability ceiling and handshake-verified Run capabilities are separate facts. Only `KataGoAnalysis` and `GenericGtp` are exposed; analysis capabilities are an optional nested group, never inferred from a saved profile. Both adapters use the same manager lifecycle. GenericGtp Ready publishes verified `gtp` facts (`protocol_version`, `name`, `version`, `commands`) with no analysis group. `game_move` is verified separately: KataGo requires bounded visits and target cancellation; GenericGtp requires the qualified GNU Go 3.8 identity and exact launch arguments documented in DEVELOPMENT. Command presence alone cannot authorize a position or ruleset.

The Run owns an immutable launch snapshot. Saving, selecting or changing Autoload cannot mutate it; pending changes compare every profile field, including argv, adapter settings and finite visits. Explicit Restart or a successful Switch adopts the latest saved profile. Active/candidate deletion protection and single-choice Autoload without fallback remain in force.

The verified analysis group independently describes selected-node finite analysis, continuous analysis, whole-game/task analysis, candidates, PV, winrate, root score, ownership, policy, visits limits and protocol cancellation. Missing snapshots are unverified; an absent analysis group admits no analysis. `game_move` admits the operation family, not every position or budget; no competitive-clock capability is exposed. During switching, primary A remains authoritative until the current candidate B promotes; a failed candidate does not replace A's capabilities or work.

GenericGtp uses one serial GTP v2 stream per run: `protocol_version`, `name`, `version`, then `list_commands`, with numeric command IDs independent of run/job identities. Ready requires `boardsize`, `clear_board`, `komi`, `play`, `genmove`, and `quit`. The single readiness deadline never renews on output. Blank-line-delimited responses support split reads, multiline bodies and CRLF. Stdout is bounded to 64 KiB per line/response, 1024 response lines and 64 queued lines; stderr is drained separately with at most 8 KiB retained for diagnostics. `command`, `protocol`, `timeout`, `process_exit`, and `unsupported_capability` distinguish rejection, malformed framing/identity, deadline, process/pipe exit and missing protocol support. A failed started GTP run seals publication, reaps its owned child and enters Error; recovery requires explicit Restart. ## Continuous Selected-node Analysis

The selected-node lane supports `finite` and `continuous` modes. Durable `continuousAnalysisEnabled` defaults to true and is loaded with the continuous budget before automatic admission. ## Data Flow

1. The user opens, replaces, or edits SGF, or imports GIB, in the React UI.
2. The frontend calls Tauri commands through API wrapper functions. Native chooser and sheet-file intake first produce `GameFileImportDto`; native Open / New / paste / import then use `prepare_document_replacement` followed by `resolve_document_replacement`. Ordinary Save / Save As use `save_current_game` / `save_current_game_as` and do not admit a document departure.
   Native cold/warm activation and main-window OS drop first pass the same external-file admission owner, then use the same `read_game_file` result and replacement path. The initial activation is consumed only after preferences/recovery arbitration; warm requests and drops are admitted only while the frontend is ready and no file/leave interaction is active.
3. Rust decodes and parses GIB into validated canonical SGF, parses SGF into DTOs, and replays positions through `sgf` and `go-core`. The holder keeps the selected `NodePath` with the document; an imported GIB has no writable native path.
4. The user edits saved engine profiles and Autoload Default in Engine Settings. Manual Check Assets is diagnostic, not a Start gate.
5. The Engine Switcher starts, stops, restarts, or switches a manager-owned Foreground Engine Run. `engine-manager` validates assets, spawns KataGo, and publishes Ready only after adapter readiness.
6. Selected-node and whole-game analysis jobs occupy that Ready Run. `katago-protocol` builds JSONL; `engine-manager` writes it to the resident process, emits progress, and cancels by run/job identity.
7. Responses are normalized into `AnalysisFrameDto` and classified by `analysis-core`.
8. Identity-valid finite completion and continuous progress/final analysis attach to the exact SGF node. Ordinary Save / Save As persists the invocation-time document while analysis continues. Confirmed-departure Save during replacement or exit first seals/stops document analysis, then saves before installing a candidate or finishing teardown.
9. Launch calls `inspect_current_game_recovery`. Restore / Discard apply or drop the envelope through the recovery commands. Restoring a game does not resume a Foreground Engine Run or Analysis Job.
10. File Exit and window close call `prepare_application_exit` / `resolve_application_exit`.
11. The UI renders board state, winrate, candidates, PVs, ownership, policy, and problem markers from DTOs.

## Persistence

Current app-data persistence includes:

- `lizzieyzy-next-engine-profile.json` for multiple engine profile settings.
- `lizzieyzy-next-app-preferences.json` for categorized durable app preferences.
- `current-game-recovery.json` for the current-game recovery envelope.

Attached analysis lives in the SGF document. There is no separate durable analysis-cache command path. The recovery envelope snapshots that document, including attached analysis, for session recovery; it is not a Foreground Engine Run or Analysis Job checkpoint.

## Boundaries

- UI code should call wrapper functions in `apps/desktop/src/api` instead of scattering raw `invoke` calls.
- Tauri commands should return structured DTOs or explicit string errors.
- SGF, Go rules, KataGo protocol, analysis classification, engine execution, and storage should remain separate domains.
- Provider integrations such as Fox, Yike, and readboard should be modeled as providers or sidecars behind Rust/TypeScript boundaries, not as UI-specific shortcuts.
- Provider/readboard code should have offline contract or domain tests before being wired into release claims. In the current batch, the acceptable repository-level claim is that offline contracts and runtime command wiring/path plumbing are implemented where the owning code lands. That is not the same as a live external provider claim.
- Live Fox/Yike network behavior and live readboard sidecar behavior require separate environment validation with real credentials, network access, target client state, and sidecar process evidence.
- Java/Swing files are behavior references during this migration track and should not be edited for Next scaffold validation.
