# LizzieYzy Next Architecture

LizzieYzy Next is the Tauri 2 + Rust + TypeScript desktop architecture being built beside the Java/Swing maintenance line. The goal is to move user-visible behavior into smaller testable domains without claiming full legacy parity before the evidence exists.

## Current System Shape

```mermaid
flowchart LR
  UI["React + TypeScript UI\napps/desktop/src"] --> API["Frontend API wrappers\n@tauri-apps/api"]
  API --> Tauri["Tauri 2 command gateway\napps/desktop/src-tauri"]
  Tauri --> Model["app-model DTOs"]
  Tauri --> SGF["sgf\nparse / replay / serialize"]
  Tauri --> Go["go-core\nboard rules"]
  Tauri --> Kata["katago-protocol\nanalysis JSONL"]
  Tauri --> Engine["engine-manager\nrun / jobs / process"]
  Tauri --> Analysis["analysis-core\nmarkers / sorting"]
  Tauri --> Prefs["app-preferences\napp data JSON"]
  Tauri --> Recovery["current-game-recovery"]
  Tauri --> Match["match-core\nroles / turns / terminal rules"]
  Engine --> KataGo["Local KataGo process"]
  Prefs --> AppData["Tauri app data"]
  Recovery --> AppData
```

The UI consumes DTOs and view models. It does not consume raw KataGo JSON and does not own long-running engine processes. `engine-manager` owns the Foreground Engine Run, Analysis Jobs, and process lifetime. Rust owns file I/O, SGF parsing, process execution, cancellation, and app-data persistence.

Provider and readboard live paths follow the same boundary rule. The React UI enters through frontend API wrappers and Tauri commands; provider HTTP parsing, readboard process/socket lifetime, protocol parsing, and DTO normalization belong behind Rust crate boundaries. A wired command is repository evidence, not external-environment evidence. The fixed Windows readboard readiness run is recorded in DEVELOPMENT; Yike/Fox live sessions and readboard target synchronization retain their separate gates.

## Modules

### `apps/desktop`

React + TypeScript desktop UI built with Vite. The current UI includes board rendering, SGF text/import workflow, native SGF/GIB open and SGF save entry points, winrate and analysis panels, and engine profile controls.

The browser preview can exercise UI fallback paths and local demonstration analysis, but it cannot perform native file dialogs, authoritative current-game edit/Save, app-data profile or recovery persistence, local asset checks, or real KataGo execution.

Function Search is a session-only offline consumer of `src/i18n/resources.ts`. Resource keys use `<owner>.<subject>.<purpose>`; `ResourceKey` is derived from the complete Chinese compatibility bundle. New consumers add their base text there and import the single `t` entry point. `resolveEffectiveLocale` canonicalizes an explicit tag and defaults missing/invalid configuration to `zh-CN`; `createTranslator` resolves an optional partial bundle by that tag and falls back per missing/blank key to the complete base. Source English/Chinese/pinyin keywords are independent of translated labels. This foundation does not define the final supported-language whitelist or persist a language preference. The first actual search consumer reaches Shortcut Reference and the non-first candidate-limit setting through its existing owner.

The complete search catalog derives actions and platform chords from the Shortcut Registry, plus explicit Preferences, Engine Settings, Game Info, About and Human/PK menu targets. Each registry action must provide `action.<registry-id>` in the complete base bundle. Availability reasons describe current runtime, document, Match, trial/scoring, engine and pending-operation guards; execution calls the original bound action or menu owner. Filtering never executes an action or starts a Run. Ctrl/Command+K preserves the registry's editable-input, dialog and composition exclusions. N remains an explanatory no-op; New is Ctrl+Home, with no Ctrl+N. The actual Human New/Continue menu entries retain their Match dialog owner.

Authoring search targets include all six black/white/alternate add and list-insertion modes plus Continue Ladder. They call the same App authoring owner as Edit/Game menus; the five transform targets derive from the registry and complete base resources. Browser preview, Match, external sync, temporary modes and pending document edits retain their original availability guards. Search does not create another board-input or history owner.

`focusNavigation` owns one activation-fenced focus request. Search captures the source before pointer-driven chrome takes focus, keeps query/selection only in session memory, and restores the still-visible source component on Cancel, then its owner anchor or workspace. A destroyed owner receives no late focus. Settings wait for mount and `document.hasFocus()` before focusing an explicit `data-search-target`; unavailable controls report a reason and use the legal owner, never an arbitrary first input. A newer request, dialog or unmount cancels the old request. Game Info defaults to Komi and accepts explicit black/white name targets; cancelling a search-origin editor reopens the retained search session. Metadata submission/history remains the existing SGF-13 owner.

Function Search interprets Enter as selected-result execution only from its query input. Result and Close buttons retain their native keyboard activation and existing click owners: result activation executes that available result exactly once, while Close activation only cancels and restores the legal source. Tab/Shift+Tab stay within the panel; Escape and pointer Close use the same cancellation owner.

About obtains the native version from Tauri's current-build `getVersion` through `api/buildIdentity.ts`; a browser preview instead labels its package version as non-native. `build-identity.json` centralizes source, Issues and Help addresses. Unconfigured release/update/support identities are non-actionable; native version and opener failures remain visible. Cargo repository metadata points to the Next source repository. Product, binary, identifier and app-data/settings ownership are unchanged; installed release/channel acceptance remains separate.

The historical shell cuts remain narrowly inherited from [Ticket08 Answer](../.scratch/migration-coverage-audit/issues/08-decide-application-shell-dispositions.md#answer): [SHELL-04 census](../.scratch/migration-coverage-audit/research/01-application-shell-entry-points.md#shell-04-read-only-launch-read), Java `Lizzie.java:432–437` / `Menu.java:6547–6550`, is the abandoned argv-`read` status/engine-menu-hiding mode, not No-engine Mode equivalence. [SHELL-09 census](../.scratch/migration-coverage-audit/research/01-application-shell-entry-points.md#shell-09-force-exit), `Menu.java:429–441`, is the abandoned permanent File → Force Exit / `System.exit(0)` action. Next retains No-engine review and APP-03 Save/Discard/Cancel exit, with Retry/Exit anyway only after named teardown timeout. This records the original resolved decisions; it neither restores those cuts nor broadens Accepted scope.

`apps/desktop/src/workspace` owns left/right ratio drafts, their visible projection, pointer/keyboard resizing, and element measurement. `useWorkspace` exposes the persistence owner and default restoration; `projectWorkspace` and `resizeWorkspace` are pure, and `Workspace` consumes them without IPC. App retains SGF, selected-node and analysis ownership. Visible column minima are 210/360/240 CSS px with separate 8px separators; insufficient space scrolls rather than changing preferences. Unset shares use 228/260px above 1180px workspace width, otherwise 210/240px. Hidden shares remain stored, their pixels go to the center, and finite nonnegative shares must sum below one; a large hidden share can therefore limit the remaining rail's custom proportion. Separator bounds report that feasible range.

Main board, sub-board and winrate chart consume `useElementSize` (ResizeObserver, DPR change and window resize). Zero-size surfaces wait for visibility; unchanged measurements are filtered before scheduling React state. Bitmap dimensions track measured CSS content dimensions times DPR independently of analysis frames. Rectangular board geometry and input callbacks remain owned by their existing consumers.

`domain/renderWinrateChart.ts` owns the chart's live and 1600×600 export rendering. Both consume one selected-line model with an entire-series perspective (ADR0001), preserve unanalyzed gaps and distinguish the highlighted baseline from ordinary grid lines. Score text names the actual black-frame leader independently of plot perspective; current, hover and endpoint labels occupy separate areas. `domain/chartExport.ts` freezes selected paths, attached analyses, visibility, scale, bars and marker at invocation, before asynchronous destination selection. It is read-only: document edits, analysis admission and preference persistence remain with their existing owners. Export requires at least one valid attached metric in an enabled series; valid data in a hidden series cannot admit export. Missing visible data is refused before destination selection, while one valid isolated visible point remains exportable.

File → More Save → Save winrate chart and registry-owned Shift+Alt+S call the same App consumer, which captures and paints the invocation model before `api/export.ts::exportRenderedImage(snapshot, {defaultFileName, pngOnly: true})`. The shared Rust image-export gateway performs PNG encoding, destination/overwrite confirmation and atomic replacement, then records the unique success-only Recent Image Export Directory through PreferencesState. Mainboard export uses that same API without chart options. The prefill is the SGF basename stem plus `-winrate-m<selectedMove>.png`, or literal `untitled` without an SGF source. Registry-owned square marking is Shift+Alt+Q; menu, reference and search obtain their displayed chords from that registry.

Nullable `workspaceShares: { left, right }` is stored in the existing app preference file; missing or invalid ratios load the default strategy. The narrow `update_workspace_shares` command merges under `PreferencesState`'s transaction lock, atomically persists, then publishes. Ordinary full preference saves retain the backend's committed ratios. Layout writes do not re-admit analysis. The frontend renders drafts immediately, coalesces for 500ms and serializes writes; stale completions cannot replace newer drafts or clear their pending/error state. The fixed tool area reports saved/pending/saving/unsaved and Retry saves the newest draft. Display → Restore panel sizes and Preferences share one action, changing only ratios to `null`; viewport clamps are never persisted.

File Exit and native Close drain layout, window geometry, rail visibility, native pin transactions and ordinary preference writes (including theme) before document departure. The shared drain has a five-second deadline and Retry/Cancel close on failure; it includes writes queued behind an active preference save. A failed preflight does not enter document departure or stop analysis. The existing workspace freeze owner rejects new R7 edits in handlers and disables their controls while document confirmation is active or a committed final drain remains incomplete; cancellation restores interaction and retains drafts. `finishNativeExit` repeats the all-owner drain, and Rust `confirm_native_exit` seals the latest native geometry immediately before `app.exit`. Existing document Save/Discard/Cancel, recovery and teardown contracts remain authoritative.

Nullable `windowGeometry` shares the existing atomic preference file. Its outer origin is physical pixels; client dimensions are logical pixels with the sampled `scale_factor`, and `maximized` is independent of normal bounds. The Rust window actor serializes native sampling, 500ms coalesced narrow saves, reset, Retry and exit flush without holding the preference mutex across OS calls. Minimized and transitional bounds cannot replace normal geometry. Full preference saves preserve the committed geometry just as they preserve workspace shares and Recent history.

On native Wayland, `windowGeometry.x` and `y` are both `null`: the compositor owns placement and the actor restores only logical client dimensions and maximization. Numeric origin pairs remain the Windows/X11/macOS wire contract. A mixed null/numeric origin is invalid. Wayland startup does not require a primary monitor or global coordinates, and unavailable positioning does not fail the exit fence. Reset uses the current output's available client dimensions without moving or centering the window; the compositor enforces placement constraints. Returning a null-origin record to a positioned backend uses the normal reachable-default recovery policy.

`app-preferences::window_geometry` owns deterministic sampling and restore policy. Valid, title-reachable saved rectangles remain in place; invalid rectangles fit the default 1440×900 client to the primary work area. A reachable rectangle needs at least 100 logical pixels of draggable width and `min(32, native draggable caption height)` logical pixels of draggable height wholly within one work area. Windows uses native caption metadata and `WM_NCHITTEST` to exclude the system icon, caption buttons and resize borders. Linux measures a native GTK HeaderBar and its allocated internal controls on the GTK thread: X11 installs that GTK decoration, while Wayland retains Tao's existing HeaderBar. GTK child visibility is measured independently of the hidden toplevel; client size excludes the header and CSD border, and restored outer positions account for GTK's gravity offset. AppKit queries the NSWindow title strip and visible standard-button bounds on the main thread. Neither non-Windows adapter uses a fixed 32-pixel estimate. Native platform acceptance remains separate from source implementation and API type-checking; a compositor/window manager can constrain requested placements.

Display and Preferences share an explicit current-monitor centered, unmaximized reset that changes only geometry. Monitor-query failure fits an independently readable primary work area for display only, retains durable geometry and suspends saving until Retry succeeds. If both queries fail, the existing OS window is shown with the failure reported. Startup applies geometry while hidden, then shows the main window even on failure. Browser preview exposes the desktop-only limitation and disables reset; native geometry is not browser window state.

Geometry autosave preserves an unconsumed preference-recovery notification. A pending move returning to already-durable bounds publishes `saved` even when no disk write is needed.

Expanded setup/scoring controls remain in the diagram's scrollable flow. Their intrinsic grid rows keep the toolbar, minimum-sized board and controls separate when vertical space is insufficient.

`AppPreferencesDto.workspaceVisibility` owns independent durable `left`/`right` visibility (both initially true), with its shared value type in `app-model`. `update_workspace_visibility` merges optional sides into the latest preferences under the existing `PreferencesState` transaction lock and returns only visibility; ordinary full preference saves preserve this owner field. UI controls commit after a successful write, retain the old state on failure, and remain available outside both rails. Hidden rails stay mounted to preserve comment drafts, AnalysisPanel tabs and node/candidate identity, but have no grid pixels, separator, focus or accessibility surface. Hiding the chart clears hover; focus inside a closing rail moves to the fixed restore control. Replay is eligible on the visible candidate-enabled main board or the visible Variation sub-board; losing both surfaces pauses without resetting the retained prefix. Hiding does not mutate SGF or stop engine analysis. Browser preview uses the same merge semantics in localStorage; native app-data/restart evidence is separate.

Personal comments remain local drafts until the explicit `应用评论` action; blur and rail visibility changes never commit them to SGF. Focus on a closing rail's separator also returns to the fixed restore control before that separator is removed.

### `apps/desktop/src-tauri`

Tauri 2 command gateway. It exposes health, SGF parse/replay, native SGF read/write, engine profile persistence, asset checks, and manager-owned Foreground Engine Run commands (`foreground_engine_snapshot`, `foreground_engine_start`, `foreground_engine_stop`, `foreground_engine_restart`, `foreground_engine_switch`, `foreground_engine_start_selected_node`, `foreground_engine_cancel_job`). Whole-game analysis on a Ready Run uses `katago_start_analyze_game` / `katago_cancel_analysis`. Current-game replacement uses `prepare_document_replacement` / `resolve_document_replacement`. Application exit uses `prepare_application_exit`, `resolve_application_exit`, `retry_application_teardown`, `confirm_application_exit_anyway`, and `confirm_native_exit`. Current-game recovery uses `inspect_current_game_recovery`, `restore_current_game_recovery`, `discard_current_game_recovery`, `retry_current_game_recovery`, and `current_game_recovery_protection`. Removed profile-to-process commands `katago_analyze_once` and `katago_analyze_game` are not registered. Native `fake_analyze` is not registered; browser-preview demonstration analysis remains non-authoritative and does not create a Foreground Engine Run.

Desktop engine command results, including match-owner operations and match-default persistence, use the Rust-only `EngineCommandResult<T>` alias with `Box<EngineFailureDto>` errors; serialization retains the existing error DTO fields and casing. Replacement and exit orchestration take named `ReplacementResolution` / `ExitResolution` requests internally. Their Tauri command payloads and managed recovery-store ownership remain unchanged.

Native chooser intake uses `read_game_file`; the sheet file input uses `import_game_bytes`. Both return `GameFileImportDto` (`format`, canonical `sgf_text`, display path/name, optional writable `native_path`, optional `opened_path`) and then enter the same document-replacement owner. Native reads canonicalize the source path and retain it as `opened_path`; byte imports have no `opened_path`. SGF/TXT retains its native path. GIB is decoded and normalized by the `sgf` crate and always returns `native_path = null`, so ordinary Save uses Save As and can never overwrite the source GIB.

Native SGF/GIB activation and main-window OS file drop share one Tauri gateway admission owner and at-most-once delivery slot. Activation resolves each file argument against the requesting process's working directory and focuses the existing `main` window; a drop supplies its native path directly. The cold-start request remains in Rust until the frontend has loaded preferences and inspected recovery. An abnormal recovery decision completes before that retained request enters `read_game_file` and the existing document-replacement owner; a normal explicit file suppresses `restoreLastSession` and sample loading. File picker, Save, replacement, recovery, and exit flows mark external-file admission busy, so later activations or drops are rejected rather than queued. No-file launches only focus; directories, unsupported types, and multiple files are explanatory non-mutating rejections.

After a native file replacement commits, chooser, activation, drop and recent reopen consume the same `opened_path` event and call `update_recent_game_history`. `app-preferences` retains five paths, newest first, deduplicating canonical paths and OS file identity (including hard links). File → Recent shows filenames with full-path tooltips, reopens through the existing safe replacement owner, and offers Clear and explicit failed-write Retry. Recent slots use Alt+1–5, Clear uses Ctrl+Shift+Delete, and Retry uses Ctrl+Shift+R through the focus-safe Shortcut Registry. Byte imports, sample, paste, New, recovery and Save do not record file-open events.

This layer should stay a gateway. Domain behavior belongs in crates unless it is directly about Tauri lifecycle, app data paths, command shape, or event emission.

Rust owns the authoritative current game. The holder stores `CurrentSgfDocument`, a monotonic semantic position/tree `generation`, `dirty`, `native_path`, the selected `NodePath`, and recovery sequence counters (`document_seq`, `snapshot_seq`). Shared results use `CurrentGameResultDto` (`tree`, `selected_path`, `snapshot`, `generation`, `snapshot_seq`, `dirty`, `native_path`). Comments, navigation and ordinary Save preserve `generation`; accepted move/tree edits and document replacement advance it. `snapshot_seq` orders document content and Save state within that identity, so delayed analysis snapshots cannot overwrite newer comments or saved/dirty state. Domain failures stay in `CurrentGameError` / `CurrentGameErrorKind`. Filesystem Save failures stay Gateway `String` errors and do not extend the domain kind enum.

Current-game mutation and derived reads are `select_current_game_node`, `play_current_game`, `set_current_game_personal_comment`, `set_current_game_metadata`, `edit_current_game_markup`, `apply_root_setup`, `convert_to_root_setup`, `remove_current_game_variation`, `promote_current_game_to_main`, `serialize_current_game`, `save_current_game`, `save_current_game_as`, and `project_current_game_mainline`. Native document replacement prepares and resolves a candidate rather than installing SGF in one command. `play_current_game` sends a `NodePath` plus point/pass vertex; Rust uses the selected position's player-to-play color and `go-core` legality. An identical existing child is selected without mutation. A new child increments document generation and marks the game dirty. Occupied, suicide, simple-ko, and invalid-path failures are atomic.

`set_current_game_metadata` takes the caller's semantic `generation` and atomically edits root `PB`, `PW`, and finite `KM`; it preserves `HA` and unrelated SGF properties. The original root values initialize the editor. One effective Apply produces one document-history unit; Cancel, invalid komi, stale generation, and no-op produce none. Name-only edits preserve generation, attached analysis, and active tasks. A changed komi advances generation, removes now-inapplicable attached `LZ`/`LZ2` analysis across the tree, invalidates old jobs/tasks, and re-admits continuous analysis with the new condition. Undo/Redo exchange the affected analysis attributes with the corresponding komi condition without restoring Run/Job/Task identities. The HUD reads current root names directly, preserving nonblank text and falling back to 黑棋/白棋 for missing or whitespace-only values; long values retain their full accessible title.

`undo_current_game` and `redo_current_game` take the caller's `generation` and return the same authoritative result, including `can_undo` and `can_redo`. The Rust document owner retains at most 100 effective user commits across move/pass insertion, personal-comment Apply, root metadata Apply, node markup, root setup/conversion, subtree deletion and mainline promotion. Navigation, choosing an existing child, failed/no-op edits, Save, preferences and analysis reports do not create commits. An effective edit after Undo discards the redo branch. The Shortcut Registry routes document Undo/Redo only outside editable text controls.

History reverses affected properties or subtrees and restores the exact pre/post-edit cursor. It does not restore a whole-document snapshot: unrelated analysis accepted since the edit remains attached. Structural and komi reversals advance semantic generation and invalidate old analysis/task identities; name, comment and markup reversals preserve generation and do not cancel unrelated work. Neither direction restores a Run, Job or Task.

The extension seam is `sgf::DocumentEditOutcome`: an effective domain operation returns its resulting snapshot and one opaque `SgfDocumentEdit`; a no-op returns no edit. `CurrentGameHolder::commit_edit` admits that unit and its revision to `sgf::DocumentHistory`. Domain Undo/Redo applies the inverse and returns `DocumentHistoryOutcome` with the exact cursor and structural flag. New authoring operations must supply affected-content inverses through this same seam, then let the holder advance generation, snapshot ordering and dirty state. Unrecorded content changes use the independent content revision; navigation does not.

`author_current_game` takes the exact selected path and generation with `SgfAuthoringActionDto`. `sgf::author_with_history` owns forced-color/alternate real moves, insertion after the selected anchor and before every ordered old child, surviving recorded/setup-stone origin edits, whole-tree SGF transforms, and the fixed Java five-coordinate ladder predicate. Every affected branch is rule-validated before live mutation. Coordinate transforms cover compressed setup/markup ranges, labels, territory, arrows and lines; rotations require a square board, mirrors support rectangles, and color exchange changes color-owned properties/result without rewriting comments or changing komi. One effective transaction contributes an affected-content inverse, invalidates affected analysis and advances semantic generation through the existing holder.

Non-inserting Add reuses an existing child with the same resolved color and coordinate, for both forced-color and alternate moves. This is navigation: the child's properties, descendants and attached analysis remain intact; history, dirty state and semantic generation are unchanged. The gateway adopts the selected path, advances snapshot ordering and follows the position for recovery and continuous analysis. Insert still creates a new position and validates the displaced descendants; it never takes this reuse path.

Authoring inverses include every affected node's analysis slots, even when initially empty. Undo/Redo exchange the complete `LZ`/`LZ2`/`LZOP`/`LZOP2` group with its corresponding position: analysis accepted after the edit or after Undo is retained for that position's next restoration, never carried onto the other position. Insertion reversals exchange descendant slots before removing the inserted node and restore them after rebasing on Redo. Later analysis on unaffected nodes remains attached; serialized SGF and reopened snapshots follow the same rule.

The gateway retains Match, trial, external-source and document-departure edit fences; drag additionally refuses a manager-owned game-move job. Canvas gesture/context intent captures the presentation identity and never publishes stale output. `AppPreferencesDto.allowDrag` maps Java `ui.allow-drag` (missing false); `allowDoubleClick` maps `ui.allow-double-click` (missing true). Both use PREF-01 successful-save publication and failed-write retention. Independent REVIEW-01 `ui.enable-click-review` is not represented by either permission. Native Windows gesture and Save/reopen acceptance remains a separate integration gate.

`remove_current_game_variation` and `promote_current_game_to_main` take the caller's `generation` with the exact `NodePath`. Delete cuts the selected non-root subtree and selects its parent; a node with children requires confirmation in the UI. Root Delete enters the existing safe New/Clear document flow. Promote moves the selected child to index zero at every branching ancestor while preserving the relative order and content of other siblings; the resulting path selects the same node. Its history inverse moves the original nodes back without copying the whole tree, including attached analysis. Already-main is a no-op. Return-to-main navigates to the mainline ancestor preceding the first off-main child, changing neither document content nor history. Structural edits and their reversals advance `generation`, invalidating old path-bound analysis and task work.
`apply_root_setup` accepts the selected childless root's complete stone set and player to play under the current `generation`; Rust validates rectangular board coordinates and duplicate points before one history commit. The UI previews black/white/erase/clear/PL locally and Cancel leaves the authoritative document untouched. `convert_to_root_setup` requires explicit UI confirmation and the exact selected path/generation; Rust replays that selected branch (including imported intermediate setup and pass), replaces the root position, and removes the move tree. It retains other root properties, the personal root comment and the native source path, while removing root analysis whose position no longer applies. Both edits reverse through the same document history, restore the previous tree/cursor on Undo, advance semantic generation and invalidate old analysis/task identities; neither starts or restores an engine.

Successful Save retains history and records the invocation-time savepoint. Dirty compares the current edit state and independent content changes against that point; later analysis cannot be cleared by returning to a saved history position. Save As adopts the new source path independently of history. Failed/cancelled Save does not move the savepoint. Successful document replacement or recovery starts with empty history; cancelled replacement preserves it. Recovery persists document content and dirty state, not history.

`select_current_game_node` requires the caller's `generation` alongside the exact `NodePath`; stale identities, invalid paths and pending departures fail before cursor/recovery/analysis changes. The frontend coalesces rapid requests within that identity and never publishes a superseded selection. Complete-tree, Selected Review Line, chart and problem-list links carry actual paths; jump-to-move counts B/W nodes including pass, skips setup/comment nodes, and uses zero for root. Navigation preserves SGF content and dirty state. Analysis accepted later retains its independent dirty semantics.

`find_current_game_recorded_point` is a generation-and-current-cursor-fenced read. `sgf::CurrentSgfDocument` resolves only coordinate-bearing B/W properties: current node, nearest matching ancestor, chosen continuation, then stable child-order root DFS for explicit all-branches search. Current-line double-click omits the root fallback. Setup, pass and off-board points do not match; repeat queries stay at an already matching node. The query never changes tree, source, history or dirty state and issues no engine request. A resulting exact path uses the existing REVIEW-01 selection owner.

BoardCanvas remains the single board gesture owner. Its existing `allowDoubleClick` permission enables current-line point review; explicit `按此点找手` in the same right-click menu requests all branches independently. Ordinary review single-click waits for classification before submitting any edit. Read-only `board_gesture_timing` returns Rust-first `BoardGestureTimingDto.double_click_interval_ms` from Windows `GetDoubleClickTime`, actual GTK window `gtk-double-click-time` on the UI thread, or macOS `NSEvent.doubleClickInterval` rounded up to whole milliseconds. The setting is read per first ambiguous click, never persisted, capped or substituted with a fixed fallback. Timing read failure visibly refuses only the ambiguous gesture; keyboard and explicit context controls remain available. Browser preview cannot supply native timing.

Pending clicks capture generation, exact selected path and presentation token plus current mode/permission. Owner change, unmount, drag, pointer cancellation and classified second click retire them. A second pointerdown pauses the first timer even when the second press is held beyond the interval; browser click detail resolves the pair. Match/trial/scoring/setup/markup/forced-authoring and disabled-double-click routes retain their existing immediate owner behavior. Point queries additionally fence live navigation/edit/departure/external-sync/engine-game ownership before request and publication and call only the existing exact REVIEW-01 selection seam.

The selected snapshot includes `markup: SgfMarkupDto[]`, projected in Rust from that node's LB/CR/SQ/MA/TR properties (including compressed point lists). The board renders this snapshot alongside its position and comments. Invalid annotation coordinates are omitted from presentation while the original properties remain preserved in SGF. `edit_current_game_markup` accepts a selected `NodePath`, `generation`, and a point tool or Clear action; the Rust owner rejects stale selection/document identity and off-board points. LB text, sequential letters/numbers and CR/SQ/MA/TR replace or erase only supported markup at the point; Clear removes only supported markup on that node. Effective actions enter document history without advancing semantic generation, cancelling range tasks or replacing unrelated analysis. The frontend offers focus-safe tool shortcuts and requires explicit Apply for text.

`stone_move_numbers: MoveDto[]` in the selected snapshot identifies successful moves whose stones survive on its actual root-to-node line. Rust replay removes captured sources and clears setup points (including same-color setup); pass advances the move count without a point label. The main board consumes this projection rather than first-child moves or path depth.

`enter_trial` / `exit_trial` transition the current-game owner through Review → Entering → Active → Leaving → Review. `sgf::TrialLine` retains only the entry's replay ancestry and trial descendants; the entry appears as move zero, while the original tree, savepoint, source path, history and recovery stay authoritative and untouched. `TrialSessionDto` carries a separate session ID and monotonic revision; `trial_select`, `trial_play`, `trial_undo` and `trial_start_finite` reject stale IDs/revisions. Trial edits use an independent undo stack and do not offer a commit-to-document path. `trial://analysis` carries only session snapshots after selected-node Job identity, revision and position checks; original SGF analysis attachment is blocked throughout the temporary mode.

Entering seals current Job publication, pauses any active whole-game Analysis Task without clearing its completion set, and awaits selected/whole-game target cancellation (five-second bound). Failed cleanup reports failure and leaves the original document intact. The manager follows trial positions for the existing continuous selected-node lane and accepts finite trial jobs on that lane; the original continuous intent is retained. Leaving cancels trial queries before resuming the original selected position, without automatically continuing a paused whole-game task. Save/Copy/recovery always use the authoritative document. Departure admission validates the replacement or original dirty decision before sealing trial analysis; Cancel leaves the trial alive, while a confirmed replacement discards it with the document transition.

`enter_scoring` / `update_scoring` / `exit_scoring` reuse the temporary-mode admission and cancellation fence but do not submit KataGo queries. Rust freezes the selected position, owns dead-group and neutral-point correction, and computes area (living stones plus owned empty points) or territory (owned empty points plus actual captures plus opponent dead stones). A dead stone's now-empty point can be owned once as territory; neutral points do not score. White receives the document's finite komi and, in area mode only, optional 0, h, or max(h−1, 0) handicap compensation. Explicit root HA or setup with a recognizable ruleset can initialize compensation; the user can correct nonnegative h without editing HA/RU/KM. ### `crates/engine-manager`

Engine profile catalog, Autoload Default, asset checks, and the manager-owned Foreground Engine Run: lifecycle snapshot, Start/Stop/Restart/Switch, selected-node and whole-game Analysis Jobs, process execution, cancellation, and typed failure.

Profiles separate the common launch fields (`name`, `program`, ordered `argv`, optional `working_dir`) from discriminated `adapter_kind` / `settings`. A whitespace-only working directory is treated as absent; nonblank paths retain every byte, including leading and trailing spaces. `kata_go_analysis` owns model/config paths and finite `max_visits`; `generic_gtp` has an empty settings object. Each argv item is one process argument, including empty strings and whitespace; no shell parsing is involved. KataGo owns the analysis subcommand and model/config flags; conflicting user arguments are rejected rather than rewritten.

Catalog version 1 keeps stable record IDs, order, settings selection and optional Autoload Default. Legacy unversioned collection and single-profile files are decoded only at the persistence boundary. Reads never rewrite the file or start a process. Unknown versions, malformed adapter settings and save failures remain observable and preserve the previous catalog and runtime. Explicit saves validate structure and atomically replace storage; executable/model/config existence is checked at Start, not Save. An unconfigured default profile is not a Ready Run.

`reorder_engine_profiles_settings` takes the caller's ordered `expected_profile_ids` and a complete `profile_ids` permutation. Under the catalog write lock, the gateway reloads the latest catalog; `engine-manager::reorder_engine_profiles` rejects stale order/membership, unknown IDs, duplicates and incomplete sets before writing. It reorders the latest saved records without changing Settings selection or Autoload Default, so independently saved profile edits survive. A same-order request performs no write. Successful atomic replacement precedes publication; failed write/replace retains the old durable catalog. The command takes no engine manager and performs no lifecycle or job operation. Catalog Save and reorder share the write lock; atomic reads remain independent of the manager's lifecycle lock.

Ordinary catalog Save owns profile contents, membership, Settings selection and Autoload, not order: Rust `prepare_engine_profiles_save` retains surviving IDs in the latest durable order and appends new IDs in their supplied relative order. Deleted IDs are omitted. This prevents a late full-catalog editor snapshot from undoing a committed reorder; the narrow order command is the only user-directed order writer. The browser-only storage fallback follows the same transaction contract.

Engine Settings renders first/up/down/last controls for each saved stable-ID row, disabling first/up at the start and down/last at the end. It calls the narrow order wrapper rather than the editor's full Save path: successful publication updates only saved catalog rows and their consumers, preserving Settings selection, Autoload controls, draft fields and asset-check state. Same-panel Save/selection/Autoload/reload and reorder are fenced while a catalog request is pending; draft inputs remain editable during reorder and completion does not reset late edits. All new labels, hints and save/error messages use the released `i18n/resources.ts` translator and compatibility fallback. Persistence failures display their full diagnostic with the unchanged list.

Saved configuration, the adapter's static capability ceiling and handshake-verified Run capabilities are separate facts. Only `KataGoAnalysis` and `GenericGtp` are exposed; analysis capabilities are an optional nested group, never inferred from a saved profile. Both adapters use the same manager lifecycle. GenericGtp Ready publishes verified `gtp` facts (`protocol_version`, `name`, `version`, `commands`) with no analysis group. `game_move` is verified separately: KataGo requires bounded visits and target cancellation; GenericGtp requires the qualified GNU Go 3.8 identity and exact launch arguments documented in DEVELOPMENT. Command presence alone cannot authorize a position or ruleset.

The Run owns an immutable launch snapshot. Saving, selecting or changing Autoload cannot mutate it; pending changes compare every profile field, including argv, adapter settings and finite visits. Explicit Restart or a successful Switch adopts the latest saved profile. Active/candidate deletion protection and single-choice Autoload without fallback remain in force.

`engine-manager::resources` binds each successful Run's optional `qualified_resource` receipt to its stable profile ID and SHA256 of the complete saved profile contents. It hashes the resolved executable, adapter-owned model/config, reachable `@include` configs and existing file-valued launch arguments before spawning and again after the real readiness exchange. File or resolved-link replacement, unreadability and a changed saved profile reject that attempt before promotion. Every explicit Start/Restart/Switch repeats qualification; no path-only or persisted qualification cache is reused. An already-running Run's receipt remains its immutable launch evidence, not a promise about later on-disk contents.

Local content identity and runtime compatibility do not authenticate a publisher. These receipts explicitly use `local_unknown`, show the version/backend actually reported by the running child (unknown when absent), and never claim a source commit or a static-zlib exemption from a local filename/manifest. Managed schema2 trust remains a separate resource-owner admission result. The actual engine readiness probe validates model/config compatibility; there is no general PE scanner or implied GPU certification. Missing/corrupt/incompatible Start remains No-engine. Failed B preserves only captured, still-live A; an exited A cannot cause alternate promotion. Neither path writes the authoritative current game.

Each content-hashing pass has a 30-second deadline independent of the protocol readiness deadline; Stop invalidates admission even while a pass is finishing. This keeps file I/O from consuming a short protocol-response budget.

Startup stderr is isolated from readiness stdout and continuously drained into an 8 KiB identity prefix plus an 8 KiB failure tail. The prefix preserves early version/backend reports while the tail preserves late loader failures; retained bytes do not grow with output. First-consumer diagnostics expose at most 8 KiB of redacted text, escape record/control delimiters, redact URLs, sensitive key-values and user paths, and identify the attempted executable and typed model/config/CUDA/cuDNN/NVRTC/TensorRT-parser/zlib cause where actually reported. File hashing uses a 64 KiB buffer; config inspection is bounded to 4 MiB/file, 32 include levels and 128 resources. A hash/read failure is not a qualification success. Settings show the current Run's content receipt separately from drafts and failed-candidate diagnostics; native acceptance remains separately recorded.

The verified analysis group independently describes selected-node finite analysis, continuous analysis, whole-game/task analysis, candidates, PV, winrate, root score, ownership, policy, visits limits and protocol cancellation. Missing snapshots are unverified; an absent analysis group admits no analysis. `game_move` admits the operation family, not every position or budget; no competitive-clock capability is exposed. During switching, primary A remains authoritative until the current candidate B promotes; a failed candidate does not replace A's capabilities or work.

GenericGtp uses one serial GTP v2 stream per run: `protocol_version`, `name`, `version`, then `list_commands`, with numeric command IDs independent of run/job identities. Ready requires `boardsize`, `clear_board`, `komi`, `play`, `genmove`, and `quit`. The single readiness deadline never renews on output. Blank-line-delimited responses support split reads, multiline bodies and CRLF. Stdout is bounded to 64 KiB per line/response, 1024 response lines and 64 queued lines; stderr uses the bounded startup capture described above. `command`, `protocol`, `timeout`, `process_exit`, and `unsupported_capability` distinguish rejection, malformed framing/identity, deadline, process/pipe exit and missing protocol support. A failed startup reaps its owned child and remains No-engine; failure after Ready seals publication and enters Error, requiring explicit Restart. Stop, Restart, promotion, failed candidates and application teardown use owned-child termination. No live run, GTP state or command stream is persisted.

Menus, shortcuts, buttons and task preview/start/continue use the same action-specific admission. Query-producing actions also require the fields actually requested: current gateway queries request ownership and policy; bounded visits and leading-candidate conditions require their respective capabilities; swing filters require the selected metrics. ### Provider crates

## Continuous Selected-node Analysis

The selected-node lane supports `finite` and `continuous` modes. Durable `continuousAnalysisEnabled` defaults to true and is loaded with the continuous budget before automatic admission. Exact SGF projection, actual Ready capabilities, immutable saved profile snapshots, process liveness and the document baseline are rechecked for every participant under the commit gate. The serialized preferences transaction writes `matchDefaults` atomically before an infallible staged SGF/history/session/run installation. Preparation, cancellation and process reaping never wait under the current-game lock. Precommit failure preserves the old document, selection, history/savepoint, native path, foreground and durable defaults; candidate cleanup affects only the owning reservation. Postcommit failures retain the committed document.

Stop or exit during Starting seals the uncommitted session. After confirmed cleanup, Start returns an ordinary `idle` / `stopped` update without a failure; it does not install the staged document or defaults. A genuine preparation failure or recorded cleanup failure remains visible. The frontend retains cancellation intent until the new Starting identity arrives, and never sends that Stop to a previous idle/error session that no longer holds resources.

Preparation refusal, including a missing saved profile on either PK side, releases the empty reservation before returning. When an uncommitted reservation releases an old foreground with nonterminal Stopping analysis, missing cancellation deadlines receive a fresh five-second bound. Transaction isolation ends at release: ordinary unresponsive-run cleanup resumes, while continuous analysis remains held.

Human/New and Human/Continue support both colors, legal moves, Pass, current-player resign and Stop. The turn token includes session, turn, generation and NodePath; engine publication additionally consumes the current run/job exactly once. Ordinary edits, navigation, ordinary analysis, competing matches and destructive run actions cannot bypass Starting/Playing/Paused ownership. Illegal human input leaves the turn intact. Illegal engine output, protocol/EOF and deadline errors seal the session with a typed failure. Cleanup retains occupancy until the manager confirms release; Stop can retry held cleanup. No ending automatically resumes analysis. Human Pause remains outside this scope; qualified Human GTP remains supported.

SGF staging writes standard size, rules, komi, player labels, actual handicap stones and PL. Start is one reversible document-history edit; each accepted move/result is privately prepared before infallible application. Resign writes `B+R` or `W+R`; two passes remain committed before the existing scoring confirmation, whose cancellation cannot revive the match. Stop/failure fabricate no result. Saves and recovery contain only committed SGF; reopening or restarting returns to review without session/run/job state. Native exit Cancel preserves the session, including an engine result waiting behind a cancelled protected Save.

Human/Continue starts from the selected node of the current document. `HumanMatchStartDto.start` is a tagged `MatchStartDto`: `new { discard_confirmed }` or `continue { node_path, root_metadata_confirmed }`. Continue requires the exact selected NodePath plus the semantic generation and the explicit whole-document metadata confirmation; it keeps the document identity, native path and dirty baseline (no departure prompt). Unlike New, Continue does not require an equal snapshot sequence before reservation: accepted continuous analysis advances `snapshot_seq` without moving the position, while structural edits and document replacement advance generation and navigation changes the selected NodePath. Once reserved, the owner still rejects installation if identity, generation, snapshot sequence, content or selection changed during preparation. The dialog pins the node and generation it displays when it opens, so a navigation landing afterwards makes the backend reject the start instead of retargeting it. Board size, rules, komi, handicap/setup and player to move are inherited from `exact_position(start)`; New-only draft fields are ignored and only participants (human color, profile, deadline, Kata visits) merge into saved `matchDefaults`. A root with black setup stones and no white/empty setup or `PL` is White to play in both the exact position and the replayed snapshot. Unsupported exact positions are rejected before reservation, I/O or mutation. `CurrentSgfDocument::stage_continuation` privately promotes the start path to mainline at every depth, inserts an empty structure node as the first child of the start, replaces root PB/PW with the match labels and removes every root RE; old continuations and comments remain variations, so the same next move creates a new node instead of reusing an old child. Install is one history edit selecting the structure node and bumps generation, so old NodePaths/turn tokens and late results are stale. Its inverse is affected-content only (result, root metadata, mainline promotions, structure-node removal): Undo restores the old tree order, players, result and selection while analysis accepted later on surviving nodes stays attached. An inherited trailing pass counts toward the double pass; structure nodes do not break the pass sequence. Zero-move Stop or resign keeps the structure endpoint without a fabricated move.

Durable defaults are 19×19, komi 7.5, handicap 0, human Black, and 30000 ms / KataGo 800 visits per request. PK adds independent `pk_black` / `pk_white` saved profile IDs and budgets, plus positive `pk_max_moves` (default 450). Rules and profiles are explicit choices. Generic GTP is limited to the qualified GNU Go 3.8 boundary for Human and PK sides; a GTP side is budgeted only by its hard deadline, and a visits budget for it is refused before any process starts. Deadlines are per-request limits, not competitive clocks. Full GAME acceptance is tracked separately in the parity matrix.

While reserved, unchanged continuous settings allow display-preference persistence; changed continuous settings are rejected before disk/cache mutation. The preferences→manager transaction holds admission through the atomic write and infallible intent/cache install. Invalid durable match defaults use the existing unreadable-preference quarantine/recovery path. Recovery establishes the analysis safety hold before publishing the restored position, even with persisted continuous intent and a Ready run. Runtime error attribution retains the committed profile/run and failed side; capability UI grants move support only from the actual matching Ready snapshot, with adapter contract restrictions stated separately.

The start form displays the complete qualified board/rules/setup/budget boundary without truncation. Per-request deadlines remain manager-enforced even when the qualified GTP adapter maps the remaining request budget through verified `time_settings` / `time_left`; that mapping does not introduce a whole-game clock.

PK reuses the New/Continue staging and history boundary above for any KataGo/qualified-GTP pairing. Continue merges both participant budgets/profile IDs and the move limit, not New-only position fields. `MatchSnapshotDto.mode`, Black/White-ordered `pk_runs`, `committed_moves`, `pause_pending`, `rebuild_sides` and `resume_pending` expose ownership without persisting live state. The manager routes both distinct resident run identities, including stdout (GTP residents keep their reader by ownership, not by the primary slot) and idle-side exits, through the existing process owner; only one move job can be active. Each side gets its own immutable profile and budget. Each GTP move fully resynchronizes with `boardsize`/`clear_board`/`komi`/`play` history, so a generated move is never replayed onto a stale engine board. Any side failure ends the whole match with side/profile/run and typed cause, reclaiming both owned residents without reviving analysis.

Pause first invalidates the owner turn and clears publication authority, publishes Paused with `pause_pending`, then performs cancellation outside the document lock. A KataGo move needs an acknowledged targeted drain; a GTP move cannot be cancelled by protocol, so its run is killed and reaped and listed in `rebuild_sides`. A side without an active move is never reclaimed. Resume is unavailable until cleanup succeeds; it retains the reservation, exact position, selected branch, side and move count and requests a fresh job with the complete side budget. Ready runs keep their identity. Only explicit Resume authorizes rebuilding a reclaimed side, from that session's immutable profile snapshot (never the saved catalog or a draft), with a new run identity and repeated readiness, capability and exact-position admission; `resume_pending` makes repeated Resume join the single attempt. Stop or confirmed exit seals reconstruction, and a late Ready never returns the session to Playing. Rebuild failure ends the match at the committed position with side/profile/typed cause, without retry or default writes; unexpected exits never earn reconstruction. Duplicate controls and late results cannot reopen a sealed turn; Stop during drain cannot be undone by Pause completion. Unconfirmed cleanup remains occupied/error, not falsely Idle. Native close Cancel preserves Paused; recovery contains committed review data only.

Only newly committed moves and passes count toward the PK limit; inherited history and structure nodes do not. Resume never resets the count. Two passes take precedence over a coincident limit and enter the existing scoring flow; typed resignation writes its standard result without adding a move. Limit, Stop and failure return to review without inventing `RE`, retrying or restarting analysis. There are no competitive clocks, automatic resignation, batch matches or human PK moves.

### Human/New and Human/Continue session analysis

`MatchSnapshotDto.analysis` contains session-only `supported`, `policy`, `epoch` and `frame`, defaulting to unsupported/off with no frame. Human New and Continue start off and offer `human_turn`, `engine_turn` and `both` policies; first enabling analysis selects both. Admission uses the committed Human run's verified KataGo analysis, candidates, visits-limit and protocol-cancel capabilities. Qualified generic GTP remains move-only and rejects non-off policies in the owner, with disabled native controls. PK always exposes unsupported/off analysis with no frame, regardless of either run's capabilities, and the backend rejects `human_match_analysis_policy` for PK. No analysis policy/frame is stored in match defaults, ordinary analysis preferences, recovery or personal `C`.

Human-turn analysis is a finite, reservation-authorized exact-position request in the exclusive move channel; its final frame remains visible until a transition. Before accepting a human move or changing policy, the owner seals publication and drains any human analysis outside the document lock. Engine-turn frames come from the actual reserved move job, never a concurrent ordinary analysis lane. The request keeps the match's compute budget. Intermediate frames use a bounded nonblocking queue; final delivery is separate. Analysis-only completion cannot grant a move-publication permit.

Frames carry session/turn, analysis epoch, document generation/NodePath and run/job identity. Monotonic snapshot revisions and complete envelope checks reject reordered, old-run/job/position and sealed events. Policy changes increment the epoch and clear output; an already-running engine move continues unchanged, but its old-epoch frames cannot return after off/on. The new policy applies to subsequently scheduled work. Turn changes, Stop, errors and endings also clear output. Session frames reuse ANA-04 rendering and display preferences without legacy black/white analysis filters or SGF attachment; ordinary review analysis remains independent.

Analysis frame/completion admission uses turn identity, not the interactive human-input gate: an exit decision or protected Save cannot swallow finite completion or its failure. This updates only session state, never the protected document. Cancel preserves successful final output; a runtime failure remains terminal. Asynchronous frontend SGF/projection artifacts follow document generation and snapshot sequence, independently of newer analysis-only session revisions.

## Data Flow

1. The user opens, replaces, or edits SGF, or imports GIB, in the React UI.
2. The frontend calls Tauri commands through API wrapper functions. Native chooser and sheet-file intake first produce `GameFileImportDto`; native Open / New / paste / import then use `prepare_document_replacement` followed by `resolve_document_replacement`. Ordinary Save / Save As use `save_current_game` / `save_current_game_as` and do not admit a document departure.
   Native cold/warm activation and main-window OS drop first pass the same external-file admission owner, then use the same `read_game_file` result and replacement path. The initial activation is consumed only after preferences/recovery arbitration; warm requests and drops are admitted only while the frontend is ready and no file/leave interaction is active.
3. Rust decodes and parses GIB into validated canonical SGF, parses SGF into DTOs, and replays positions through `sgf` and `go-core`. The holder keeps the selected `NodePath` with the document; an imported GIB has no writable native path.
4. The user edits saved engine profiles and Autoload Default in Engine Settings. Manual Check Assets is diagnostic, not a Start gate.
5. The Engine Switcher starts, stops, restarts, or switches a manager-owned Foreground Engine Run. `engine-manager` validates assets, spawns KataGo, and publishes Ready only after adapter readiness.
6. Selected-node and whole-game analysis jobs occupy that Ready Run. `katago-protocol` builds JSONL; `engine-manager` writes it to the resident process, emits progress, and cancels by run/job identity.
7. Responses are normalized into `AnalysisFrameDto` and classified by `analysis-core`.
8. Identity-valid finite completion and continuous progress/final analysis attach to the exact SGF node. Ordinary Save / Save As persists the invocation-time document while analysis continues. Confirmed-departure Save during replacement or exit first seals/stops document analysis, then saves before installing a candidate or finishing teardown.
9. Launch calls `inspect_current_game_recovery`. Restore / Discard apply or drop the envelope through the recovery commands. Restoring a game does not resume a Foreground Engine Run or Analysis Job.
10. File Exit and window close call `prepare_application_exit` / `resolve_application_exit`.
11. The UI renders board state, winrate, candidates, PVs, ownership, policy, and problem markers from DTOs.
